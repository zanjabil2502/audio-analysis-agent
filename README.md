# Audio Analysis Agent

Analyzes audio files (e.g. court deposition recordings) and produces a structured
JSON report with objective DSP metrics plus an LLM-generated, human-readable insight.

## Architecture

Two decoupled parts:

```
┌─────────────────────────┐        MCP (SSE)        ┌──────────────────────────┐
│  Agent / Workflow        │ ──────────────────────▶ │  MCP Server               │
│  (app/, main.py)         │   calls 7 tools in      │  (audio_mcp/, server.py)  │
│  LlamaIndex Workflow     │   parallel              │  FastMCP + ffprobe/librosa│
│  + OpenAI LLM            │ ◀────────────────────── │                           │
└─────────────────────────┘     metrics (JSON)       └──────────────────────────┘
```

**1. MCP server** (`audio_mcp/` + `server.py`) — exposes audio analysis as tools:

| Tool | What it returns | Library |
|------|-----------------|---------|
| `extract_metadata_tool` | duration, bitrate, sample rate, channels, codec | ffprobe |
| `detect_silence_tool`   | silence segments + ratio | librosa |
| `detect_low_volume_tool`| mean volume (dB) + flag | librosa |
| `detect_clipping_tool`  | peak amplitude + clipping flag | numpy |
| `estimate_snr_tool`     | SNR (dB) + category | librosa |
| `extract_features_tool` | spectral features + band energy (speech / hum bands) | librosa |
| `detect_glitches_tool`  | click / dropout / stutter events | numpy + scipy |

**2. Agent** (`app/` + `main.py`) — a LlamaIndex `Workflow` with 3 steps:

1. **`run_parallel_analysis`** — calls all 7 MCP tools concurrently (`asyncio.gather`).
2. **`generate_insight`** — feeds the raw metrics to the LLM and gets back a
   structured `Insight` (Pydantic) via `astructured_predict`.
3. **`build_final_report`** — returns `{ file_path, metrics, insight }`.

## Design decisions

- **MCP server separated from the agent.** The DSP tools are reusable by any MCP
  client; the agent is just one consumer.
- **ffprobe for metadata, librosa/numpy/scipy for DSP.** ffprobe gives reliable
  container/codec info; everything else is computed from the waveform.
- **Tools run in parallel** since they are independent — faster end-to-end.
- **Structured LLM output via Pydantic.** `astructured_predict` forces the model to
  return a schema-valid object, so there is no fragile JSON-string parsing.
- **No fabricated quality score.** An earlier version assigned a 0–100 score with
  hand-picked penalty weights, but those weights had no reference/standard, so they
  were removed. The system now reports **objective metrics** and lets the **LLM
  interpret** quality qualitatively. A trustworthy numeric score would need
  calibration against real labels (e.g. ASR Word Error Rate).

## Project structure

```
audio_mcp/            # MCP server: DSP + metadata tools
  core/               #   detect.py, feature.py, metadata.py, utils.py
  registry/           #   register tools onto the FastMCP server
server.py             # builds the FastMCP server
app/core/             # agent: model.py, prompts.py, schemas.py, workflow.py
main.py               # CLI entrypoint
run_mcp.sh            # starts the MCP server (SSE, port 8001)
```

## Requirements

- Python 3.13, [uv](https://docs.astral.sh/uv/)
- `ffmpeg` / `ffprobe` installed and on `PATH`
- An OpenAI API key

## Setup

```bash
uv sync
```

Create a `.env` file in the project root:

```env
OPENAI_API_KEY=sk-...
LLM_MODEL=gpt-4.1-mini
```

## Run

**1. Start the MCP server** (SSE on port 8001):

```bash
./run_mcp.sh
```

**2. Analyze audio** (in another terminal):

```bash
# single file
uv run main.py app/audio/bad_audio.mp3

# multiple files (batch -> list of reports)
uv run main.py app/audio/bad_audio.mp3 app/audio/moonlight-plaza.mp3
```

The report is printed as JSON to stdout (pipe to a file with `> report.json`).
